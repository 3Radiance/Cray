# protocol

Прикладной уровень — "сердце". Принимает поток байт от транспорта, парсит структуру пакета, проверяет auth, извлекает адрес назначения и payload. Не знает ничего про сеть.

## Ответственность

- Определяет `Protocol` трейт — интерфейс который должна реализовать любая реализация протокола
- Содержит встроенные реализации (например `tsf/`)
- Парсинг входящего пакета: magic → version → auth_token → addr → payload (стадийный пайплайн)
- Сборка исходящего пакета (клиентская сторона)
- Вызов верификаторов из `auth` на нужных стадиях

## Структура

```
protocol/
  mod.rs       — Protocol трейт + регистрация
  tsf/         — встроенный протокол (эталонная реализация)
  [custom]/    — кастомный протокол от юзера (Rust-код)
```

## Protocol трейт (минимум)

Каждая реализация обязана уметь:
- Распарсить входящий пакет из байт → структура
- Собрать исходящий пакет из структуры → байты
- Вернуть идентификатор протокола

Дефолтные реализации там где можно не трогать — чтобы написать новый протокол было просто.

## Два способа добавить протокол

1. **YAML DSL** — описать структуру полей декларативно, без Rust-кода. Для нетехнических юзеров.
2. **Rust-код в `protocol/`** — реализовать трейт напрямую. Полная свобода, полная ответственность юзера.

## Что модуль НЕ делает

- Не создаёт соединения, не знает про сокеты
- Не хранит крипто-примитивы (всё в `auth`)
- Не читает конфиг напрямую (регистрация через `config`)
