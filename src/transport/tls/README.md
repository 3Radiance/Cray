# transport/tls

Слой шифрования. Получает TCP-сокет, оборачивает в TLS, отдаёт дальше. Сам ничего не пишет в сеть кроме хендшейка.

## Ответственность

- Принимает `TcpStream` от `tcp/`
- Конфигурирует upstream acceptor по настройкам из `fingerprint`
- Выполняет TLS-хендшейк
- Всегда отдаёт `SslStream<TcpStream>` — следующий слой всегда знает что получит

## Upstream acceptor

Настраивается через `fingerprint` — там живут TLS-профили (версии, cipher suites, ALPN, и т.д.). `tls/` берёт готовый acceptor, не собирает его сам.

## Что модуль НЕ делает

- Не создаёт сокет (это `tcp/`)
- Не знает про HTTP, протоколы, auth
- Не принимает решения что делать с данными внутри TLS
