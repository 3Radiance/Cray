# auth

Весь слой верификации — "свой/чужой". Содержит закрытый реестр функций-верификаторов и функций-генераторов которые используются протоколами.

## Ответственность

- Реестр верификаторов: `hmac_check`, `timestamp_fresh`, `range_check`, `crc32_check` и др.
- Реестр генераторов (для клиентской стороны): `hmac_generate`, `random_bytes`, `now_u32` и др.
- Проверка inbound-пакета: парсинг хедеров, поиск маркеров "свой"
- Резолв имён из YAML-конфига в реальные функции (`verify: hmac_check` → `auth::registry::hmac_check`)

## Принцип реестра

Реестр закрытый — пользователь выбирает функцию по имени, но не может переопределить её логику через конфиг или DSL. Это граница безопасности: весь крипто-код живёт здесь и только здесь.

## Зависимости

- Не зависит ни от одного другого модуля проекта
- Тестируется полностью изолированно

## Что модуль НЕ делает

- Не знает про сеть, сокеты, транспорт
- Не знает про структуру конфига — `config` сам приходит сюда за функциями
