# Слои формирования трафика: `jitter` и `fragment`

Оба слоя это обычные обёртки. Они принимают любой поток и возвращают поток: без сокетов, без файлов профилей и без знания о транспорте или протоколе ниже и выше. Работают на клиенте и на сервере, в `inbound.layers` или в `outbound.layers`, в любом месте между слоем-источником (`tcp` или `unix`) и протоколом.

Они затрагивают только **запись**. Чтение проходит без изменений, поэтому каждая сторона формирует тот трафик, который сама отправляет, и настраивать оба конца одинаково не нужно.

```toml
[[outbound.layers]]
type = "tcp"
addr = "127.0.0.1:10811"

[[outbound.layers]]
type = "fragment"
size = "500-1000"

[[outbound.layers]]
type = "jitter"
delay = "10-20"

[[outbound.layers]]
type = "vless"
uuid = "11111111-1111-4111-8111-111111111111"
```

## `jitter`

Перед каждой записью ждёт случайное время и только потом передаёт данные дальше.

```toml
[[outbound.layers]]
type = "jitter"
delay = "10-20"
```

`delay` это строка с миллисекундами:

| Значение | Смысл |
|---|---|
| `"15"` | фиксированная задержка 15 мс |
| `"10-20"` | случайная задержка на каждую запись: от 10 мс и до 20 мс, не включая 20 |

`min` не должен быть больше `max`. Если `delay` не указан, задержка равна `"0"`.

Как это работает:

- Задержка применяется **на каждый вызов записи**, а не на каждый байт. Одна большая запись задерживается один раз, туннель, который пересылает много маленьких кусков, задерживается на каждый кусок.
- Во время задержки вызывающий код ждёт (обратное давление). Ничего не буферизуется.
- Чтение никогда не задерживается.
- Пропускная способность ограничена величиной `размер записи / задержка`. При записях по 16 КиБ и средней задержке 25 мс одно направление не превысит примерно 640 КиБ/с. Держите задержки небольшими или примите цену на объёмном трафике.
- Случайные числа берутся из быстрого общего для процесса генератора, который инициализируется временем. Распределение равномерное, генератор не криптографический.

Что слой делает и чего не делает: jitter меняет **момент**, когда пакеты уходят. Размеры и направления он не меняет, а равномерная случайная задержка не имитирует никакое реальное приложение. Считайте его способом сломать простую корреляцию по времени, а не маскировкой.

## `fragment`

Режет каждую запись на более мелкие части.

```toml
[[outbound.layers]]
type = "fragment"
size = "1000-1400"
```

`size` это строка:

| Значение | Смысл |
|---|---|
| `"1400"` | части не больше 1400 байт |
| `"500-1000"` | размер каждой части случайный в `[500, 1000)`, выбирается на каждую запись; `min` должен быть больше 0 |
| `"50%"` | каждая часть равна заданному проценту от записи (от 1 до 100) |

Если `size` не указан, он равен `"1400"`.

Как это работает:

- Каждый вызов записи обрезается до случайно выбранного префикса, и слой сообщает о частичной записи. Вызывающий код вроде `write_all` повторяет вызов с остатком, поэтому одна большая запись превращается в серию более мелких подряд.
- Это действует на **каждую запись всё время жизни соединения**, а не только на первые байты. Мелкие части на объёмном трафике стоят пропускной способности.
- Записи, которые уже меньше выбранного размера, проходят без изменений.
- Слой не добавляет пауз. Станут ли соседние части отдельными TCP-сегментами, решает ядро: при `TCP_NODELAY` каждая запись обычно уходит сразу, но записи, сделанные, пока очередь отправки занята, могут склеиться. Чтобы развести их по времени, поставьте в цепочку слой `jitter`.

### Куда ставить

Позиция определяет, что именно режется:

| Цепочка | Эффект |
|---|---|
| `tcp → fragment → tls → ...` | фрагментатор видит вывод TLS, включая **ClientHello**, и разбивает его на несколько TCP-записей |
| `tcp → tls → fragment → ...` | открытые записи режутся до TLS, поэтому TLS создаёт более мелкие записи |
| `tcp → fragment → protocol` | режет собственные байты протокола, для цепочек без TLS |

Это только техника разбиения. Слой не умеет отправлять поддельные пакеты, менять TTL, переставлять сегменты или трогать опции TCP, поэтому он не заменяет инструменты, работающие на уровне сырых пакетов.

## Логирование

Оба слоя пишут каждую запись на уровне `trace` с тегами `JITTER` и `FRAG`:

```bash
RUST_LOG=info,JITTER=trace,FRAG=trace ./cray --config client.toml
```

## Подводные камни

- Неверный `delay` или `size` обнаруживается, когда первое соединение доходит до слоя, а не при запуске.
- `fragment` с размером больше вашего MTU заметного эффекта не даёт, потому что ядро всё равно режет большие записи.
- Верхняя граница диапазона не включается. `"1000-1400"` никогда не даст ровно 1400, а `"10-10"` всегда даёт 10.
- Оба слоя на каждом соединении стоят пропускной способности и добавляют задержку. Измеряйте, прежде чем включать их для объёмного трафика.
